# Обсяг БД та посилання Supabase в Атласі

Розділ «Статистика» в налаштуваннях видалено. Натискання на обсяг БД в шапці Атласу відкриває Supabase у новій вкладці.

## Поточний проєкт

- Проєкт: `eksifjzzszcqsufwcbsx`.
- Usage організації: `https://supabase.com/dashboard/org/lqrkqwivpkswkgurtpsp/usage`.
- До посилання додається `?projectRef=eksifjzzszcqsufwcbsx`, щоб вибрати цей проєкт.
- Відповідно до наданої власником панелі від **14.10.2026**: план Pro, **8 ГБ виділеного диска**.

Показник `42,6 МБ` — виміряний обсяг самої БД з наявного `get_db_size()`. 8 ГБ — виділений диск із наданого звіту, не результат цієї функції. Смужка показує **частку БД від зазначеного диска**, без WAL та системних файлів. Це не показник зайнятості всього диска. Значення диска не оновлюється автоматично при зміні тарифу/масштабуванні; актуальний стан доступний за посиланням.

## Інші проєкти

Публічні дані належності проєкту організації та відомого обсягу диска зберігаються в `src/config/supabaseUsage.config.ts`, окремо для кожного **project ref**.

Для нового проєкту додайте його власні `organizationSlug`, `provisionedDiskBytes` і дату підтвердження. Не копіюйте значення від чужого проєкту. Якщо відповідного запису немає, посилання відкриває власну панель `/dashboard/project/<ref>`, а невідомий ліміт і відсоток не вигадуються. Organization slug неможливо отримати з одного лише project ref без додаткового джерела.

## Трафік

- Посилання й параметри диска формуються локально, без HTTP/RPC.
- Клік по посиланню не запускає додаткове оновлення розміру БД у застосунку.
- Обсяг БД використовує один компактний RPC та спільний кеш на 5 хвилин; паралельні виклики об’єднуються.
- Фото Атласу залишаються з ручним перерахунком та кешем, без автоматичного обходу папок після кожного повідомлення.
- Токени керування, нові змінні Vercel, SQL-міграції та Edge Functions не потрібні.

Пояснення диска: https://supabase.com/docs/guides/platform/manage-your-usage/disk-size
