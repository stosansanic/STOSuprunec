# Редактор акта: продовження ТЗ-02 (08.10.2026)

## Виконано

- Вилучено повне читання sclad із loadGlobalDataOnce. Відкриття акта читає лише складські ID з його рядків, пакетами до 100.
- Однакові набори ID об'єднують запит; успішні записи мають окремий TTL 5 хвилин. Помилка будь-якого пакета не публікує частковий результат.
- Частковий складський кеш більше не приймається за повний лише тому, що масив непорожній. Автодоповнення явно завантажує повний склад, коли це справді потрібно.
- Попередження кількості/ціни та наведення на каталог читають лише потрібні ID; масова перевірка спочатку збирає ID всіх рядків в один набір.
- Застаріла відповідь після інвалідації чи Realtime-події не перезаписує нові залишки. Перевірка після await також не змінює попередження для вже заміненої позиції рядка.
- Збережено всі різні sclad_id, навіть коли каталог, округлена ціна та кількість однакові. Попередня дедуплікація за цими полями приховувала різні партії.
- Голосовий пошук отримує повний склад лише при запуску голосового введення; перевіряється, що користувач не перейшов до іншого акта під час завантаження.
- Наявні серверні перевірки та записи залишків не замінені частковим кешем.

## Що ще не відповідає повному ТЗ-02

Довідники works/details поки читаються повністю, оскільки їх використовують синхронна класифікація рядків, старі назви без ID, збереження, закриття акта й голосовий пошук. Механічне спорожнення цих масивів змінить типи рядків та прив'язки. Автодоповнення складу також ще викликає повне читання за першої взаємодії. Потрібен узгоджений перехід цих споживачів на серверний пошук та явні типи/ID; цей пункт не позначено повністю завершеним.

Ця зміна прибирає повний склад при звичайному перегляді акта та перевірці його рядків, але не заявляє усунення всіх повних читань редактора.
