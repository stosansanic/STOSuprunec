# Підвантаження списку Нової пошти

За замовчуванням спочатку завантажуються всі збережені ТТН за останні 14 календарних днів включно із сьогодні. Якщо їх понад 50, початковий період читається послідовними пакетами по 50 до завершення цього періоду. При прокрутці додаються старіші ТТН по 10, за межами початкових 14 днів. Уже показані рядки не перечитуються. Якщо початковий період порожній, підвантаження історії запускає видимий нижній індикатор. Для вручну вибраного іншого діапазону дат підвантаження обмежене цим діапазоном. Пошук за актом зберігає пошук за всі дати.

Рядки дописуються до наявної таблиці. Кнопок переходу сторінками немає; кнопка «Повторити» з’являється лише при помилці. Фільтри скидають список, а пізні відповіді попереднього запиту відкидаються. Закриття модалки прибирає observer і таймер.

Пошук і статус застосовуються на сервері до пагінації. Враховуються дати, напрямок, номер акта. Пошук за номерами прив'язаних актів враховує право користувача на акт. Підвантаження не викликає API Нової пошти; оновлення від провайдера залишається окремою дією.

Порядок встановлення:

1. Виконати `20261011123102_nova_poshta_infinite_scroll.sql` після міграцій наявного архіву Нової пошти. Копія розміщена у `supabase/migrations-by-date/10.11.26/Інші міграції/`.
2. Оновити Supabase Edge Function `nova-poshta` з репозиторію разом із її shared-залежностями.
3. Оновити frontend на Vercel.

Створюється тільки RPC `np_archive_list_v2`; нових таблиць немає. Попередній RPC і гілка Edge для старої пагінації збережені, тому SQL та Edge можна встановити перед frontend. Ця міграція залежить від архіву НП і не додається автоматично до загального файла №8 для проєктів без модуля НП.

Production не змінювався. Offset-пагінація читає актуальні дані, а не зафіксований snapshot: паралельні вставки/видалення можуть змінювати межі сторінок. Повторні ТТН при дописуванні не додаються.
