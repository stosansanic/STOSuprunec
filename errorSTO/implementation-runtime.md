# Виконання та перевірка runtime-оптимізацій

Дата: 06.10.2026. Локальний код, без запуску міграцій, звернень до робочої БД або деплою. Статуси нижче стосуються повних вимог `bag.md`; «частково» не означає завершення всього пункту.

| Пункт | Стан | Зміни та межі |
|---|---|---|
| 02 | Частково | `globalCache.ts`: об'єднано одночасні однакові читання й `loadGlobalData`; покоління інвалідації не дозволяє позначити старе завантаження свіжим; помилка сторінки не видається за повний довідник; порожній склад має окремий прапорець завантаження. Редактор досі використовує повні довідники, TTL загальний. Вилучення цих даних без переведення всіх autocomplete/цінових споживачів на нові контракти зламає роботу. Повний ресурсний кеш та ізоляція за користувачем ще не реалізовані. |
| 03 | Частково | `offlineDB.ts`, `offlineSync.ts`: одна pending-синхронізація, спільна транзакція публікації успішних результатів, незаписані локальні акти не перезаписуються; помилки не оновлюють `lastSync`. Проєкції списків відкидаються також у функціях запису IndexedDB. Повне стартове офлайн-завантаження збережено: компактний список актів не замінює їхній документ. Немає повної ізоляції IndexedDB/черги за користувачем, метаданих повноти кожного ресурсу, reconciliation видалень та гарантованої пагінації всіх довідників. |
| 15 | Частково | `planyvannya.ts`: координатор оновлень з повторним проходом для подій під час завантаження; повторний місячний refresh після рендера пропускається для тих самих місяців; додано pending за роком/місяцем для паралельних читань. Межі місяця тепер від локального початку до початку наступного місяця, без обрізання UTC-дати. Зайнятість досі рахується локально; серверні агрегати й повний DTO події не готові. |
| 16 | Частково | `planyvannya_realtime.ts`: після помилки/timeout та повторного SUBSCRIBED узгоджується видимий період. Старі локальні оновлення довідників збережені. Повний реєстр підписок із ref-count та спільний detail-потік глобального/локального акта ще не реалізовані. |
| 17 | Частково | `actPresence.ts`: pending acquire об'єднано; дубльована підписка очікувача та невикористана UPDATE-підписка прибрані; heartbeat перевіряє втрату володіння, зупиняється й переходить у режим очікування. Додано покоління відкриття: пізня відповідь після закриття/зміни акта не створює нових таймерів/каналів. Частоти 30/5 секунд збережені. Повна серверна перевірка lease під час кожного запису потребує окремого узгодження наявних RPC. |
| 18 | Частково | `aiReminderChecker.ts`: браузерні вкладки координують перевірку через Web Locks та час останнього успіху; ручний запуск обходить паузу. Це не серверний lease і не гарантія від дублювання між різними пристроями. Реально встановлені cron та серверний протокол claim/timeout не перевірялися; автоматичні механізми не відключались. |
| 26 | Частково | `actSafeWrite.ts`: вузький patch повторно використовує вже прочитаний baseline, умовний запис за revision/date лишається. Черга офлайн не видаляє конфлікт після ліміту спроб. Виправлено підтвердження повтору: збіг `data` достатній лише коли збігається й `avans`, якщо він заданий; контрольне читання включає це поле. Повна атомарна перевірка payroll, legacy revision та права на сервері не завершена цими змінами. |

Збережений `oldNumbers` використовується до мережевого читання. Повної моделі snapshot/revision для всіх подій ще немає; фінальна перевірка складу залишається серверною. |
| 28 | Реалізовано локально | `zberechennya_zmin_y_danux_aktu.ts`: ціни завантажуються лише для унікальних ID із початкових, свіжих і поточних рядків, включно з вилученими, порціями по 200. Відсутня ціна потрібного ID зупиняє запис замість підстановки нуля. Потрібне приймання на копії БД для повернень і конкурентного оновлення цін. |

HTML fallback не кешується як JS/CSS. Повна ізоляція за обліковим записом працівника, якщо кілька працівників використовують однаковий Supabase JWT, не доведена. Потрібна окрема узгоджена зміна offline-контракту перед видаленням REST fallback. |

## Перевірка цієї ітерації

- `npm run check` (`tsc -b`) завершився успішно після правок runtime.
- Переглянуто diff на повторні читання, помилкову повноту, втрату чернеток і завершення асинхронного відкриття після закриття.
- Наявні сторонні UI-зміни в тих самих файлах збережено; їх не приписано оптимізації трафіку.
- Реальні байти, поведінка двох браузерів, рольові переходи, відновлення IndexedDB і серверні конкурентні записи не перевірені цим локальним TypeScript-контролем. Відсоток економії не заявляється.

## Пріоритет продовження

1. Єдиний контекст доступу для глобального кешу, IndexedDB, черги та Service Worker: потрібна перевірка реальної моделі логіна працівників, не лише Supabase JWT.
2. Поступово замінити споживачів повних редакторських довідників на адресні запити, залишивши явну повну офлайн-проєкцію.
3. Серверні агрегати планувальника з еквівалентністю чинної формули та перевіркою всіх меж/пагінації.
4. Серверний claim нагадувань і контроль lease запису після перевірки чинних функцій/cron. Не вимикати робочі перевірки на підставі самих локальних SQL-файлів.
