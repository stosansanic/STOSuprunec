# Склад і експорт: стан виконання ТЗ

Дата: 05.10.2026. Це звіт фактично внесених змін, а не позначка завершення всього ТЗ.

## Впроваджено

- ТЗ-08: у формі одиничного складу підказки деталей отримують ID і назву одним RPC `traffic_detail_suggestions`, по 20 результатів, із кнопкою «Ще». Focus/click об'єднані за ключем запиту. Дозволено початкову добірку та пошук з одного символу. Ручна зміна скидає прив'язаний ID. Вибір через pointerdown/mousedown/click обробляється один раз, отже не запускає три читання відповідального працівника. Пізня відповідь не застосовується до вже зміненого поля.
- ТЗ-09, частково: на початку масового запису до 100 унікальних назв постачальників/деталей визначаються одним `traffic_reference_ids`. Для вже знайдених назв прибрано подальше повторне читання ID та `ensure...`. Для решти використовується цільовий `traffic_reference_id` замість широкого сканування details. Наявні історичні дублі збережено: точне написання пріоритетне, далі найменший ID. Створення залишається через чинний CRUD, тому нової гарантії конкурентного створення немає.
- ТЗ-10, частково: при заповненні форми за складською позицією ID постачальника і деталі визначаються вузькими RPC. Замість двох вибірок до 1000 записів передаються два ID.
- Усунено незавершені посилання `detailsCache/lastDetailQuery` та невикористане `saved`, які заважали компіляції попередніх змін.

## Установлення й сумісність

Міграція `supabase/migrations/20261005010000_traffic_detail_suggestions.sql` додає лише функції читання. Вони SECURITY INVOKER, використовують поточні права/RLS; таблиць, переписування даних або підвищення прав немає. Функції підтримують текстові та об'єктні назви. У коді є сумісність зі старою БД тільки для відсутньої функції (PGRST202/42883); помилка доступу/мережі не перетворюється на дозвіл створити новий запис. До встановлення міграції старі широкі запити можуть залишатися. Міграцію в робочу БД не застосовано.

## Що залишається

| Пункт | Стан / причина |
| --- | --- |
| 06 | Не завершено: початкове масове вікно все ще завантажує каталоги/довідники. Потрібна спільна заміна всіх локальних підказок і OCR lookup, а також збереження чернеток між сторінками. |
| 07 | Не завершено: каталог відбирається після завантаження сторінок. Серверний відбір потребує еквівалентної NFKC/Unicode-нормалізації та нової пагінації без втрати незбережених рядків. Простий LIMIT дав би неповний результат. |
| 08 | Основний вузький пошук зроблено; повний fallback до встановлення RPC залишається. Кеш підказок обмежено формою; міжформову інвалідацію ще не реалізовано. |
| 09 | Пакетне читання ID зроблено. Атомарне створення всіх довідників і конкурентний захист повторного оприбуткування залишаються окремою незавершеною частиною. |
| 10 | Цільове визначення ID зроблено. Початковий перелік складських позицій і постачальників ще потребує серверної пагінації. |
| 22 | Протокол маніфестів не реалізовано. Подвійна перевірка експорту навмисно збережена, щоб не назвати неперевірену копію перевіреною. UI вже має захист від повторного запуску. |
| 23 | Пряма передача PDF/попередній перегляд збережені. Пакетне OCR зіставлення та серверна ідемпотентність оприбуткування не завершені. |

## Перевірка

Запущено `npx tsc -b --pretty false`. У власних змінених модулях помилок не виявлено; загальна збірка на час перевірки зупинилася на TS7022 у `tablucya.ts:1746` і `workshop/service.ts:46` (паралельні модулі інших виконавців). SQL не виконувався; конкурентні та браузерні сценарії ще не перевірено. Кількісну економію production Egress не виміряно.
