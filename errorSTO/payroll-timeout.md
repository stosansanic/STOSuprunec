# Зарплата: тайм-аут SQL 57014 — 12.10.2026

## Спостереження

На скриншоті запит зарплати повернув `57014: canceling statement due to statement timeout`. Це підтверджує перевищення ліміту виконання SQL. Фактичний план і тривалість на робочій базі не отримані: у цій сесії немає доступного підключення Supabase для виконання запитів.

## Знайдені витрати в коді

- `traffic_payroll_validate` перевіряла кожний акт через пошук у масиві вже побачених актів і дописувала цей масив. Вартість зростала зі збільшенням історії.
- `traffic_payroll_report` спочатку розгортала історію, приєднувала акти та обчислювала роботи; дату застосовувала пізніше.
- Приєднання використовувало `acts.act_id::text`, а не безпосереднє порівняння індексованого номера акта.
- Матеріалізовані проміжні рядки робіт несли повний JSON нарахування разом із масивом робіт. JSON актів також розбирався повторно.
- Обгортка v2 прибирала непотрібні підказки з уже сформованого результату, але не пропускала їх обчислення.

## Виправлення

Міграція [20261012131746_traffic_payroll_report_timeout.sql](../supabase/migrations/20261012131746_traffic_payroll_report_timeout.sql):

1. Замінила перевірку через зростаючий масив групуванням. Перевіряє дублікати у всій історії вибраних працівників, включно з датами поза звітом.
2. Для режиму відкриття відбирає дні до розгортання актів. Для закриття застосовує фактичну дату після приєднання акта, до розгортання робіт. Для оплати використовує дату оплати конкретної роботи/нарахування.
3. Приєднує акти за числовим первинним ключем. Некоректні, неканонічні та завеликі старі номери не перетворюються помилково на інший акт.
4. Читає прапорці акта один раз для кожного унікального номера та зберігає у проміжному наборі тільки ці прапорці.
5. Для підсумків і сортування використовує скалярні поля. Повні зарплатні фрагменти приєднує до 50 відібраних рядків для чинного захищеного збереження.
6. `p_options=false` пропускає формування підказок актів і робіт. Обидві версії RPC використовують одну оптимізовану функцію.

Підсумки обчислюються за всіма відповідними рядками до пагінації. Формули, індекси робіт, права RLS і серверні перевірки виплат збережені. Нових таблиць немає; ліміт виконання запитів не підвищується.
