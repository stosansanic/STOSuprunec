# Робота з журналами без зайвого сканування

## Щоденний контроль

Раз на день відкрити Usage, перевірити вибрані організацію, проєкт і платіжний цикл. Записати дату, Ingestion, Query, приріст за повний день, прогноз до кінця циклу. Не запускати автоматичне опитування Logs Explorer для цих показників.

## Пошук проблеми

1. Записати приблизний час події, функцію/маршрут і вид помилки.
2. Почати з одного проєкту, одного джерела та інтервалу 15 хвилин навколо події.
3. Фільтрувати сервіс/статус у самому запиті. За відсутності результату розширити до години, потім до дня.
4. Не повторювати той самий запит без нової події. Використати отримані результати для поточного розбору.
5. Не залишати автооновлення після завершення діагностики. Не вивантажувати весь місяць заради однієї помилки.
6. LIMIT обмежує результат, але не гарантує обмеження сканування. Якщо доступний scanned bytes, записати його.
7. Під час розбору не пересилати повні payload, токени й персональні дані у звіти.

## Перший локальний пакет 11.10.2026

Змінені Edge Functions: `check-reminders`, `send-telegram`, `smsclub-send`, `telegram-bot`.
Спільна залежність: `supabase/functions/_shared/operationalLog.ts`.
Публікувати функції разом із цією залежністю через штатне розгортання репозиторію. Самостійне копіювання лише index.ts не включає shared-модуль. SQL-міграція для пакета не потрібна.

- Успішні відповіді Telegram/SMS/webhook більше не друкують provider body.
- HTTP-помилки цих відповідей дають коротку подію зі статусом.
- Нагадування без зміни результату/без виконаної умови не створюють власний лог на кожен елемент.
- Якщо були доставки, створюється один підсумок `reminders.completed` із processed/sent/skipped; якщо доставок немає — підсумок лише в debug.
- Існуючі інші журнали помилок збережені; це не повна санітизація всіх функцій.
- Помилка запиту кількості нагадувань повертає 500 замість хибного успішного «0 нагадувань».

Debug: за потреби задати Edge secret `OPERATIONAL_DEBUG_UNTIL` з коротким терміном у форматі ISO UTC, наприклад час через 30 хвилин. Після цього часу helper автоматично перестає писати debug-події. За відсутності/некоректного/простроченого значення debug вимкнено. Не задавати далекий строк. Цей параметр не вмикає друк тіл запитів або відповідей.

## Межі ефекту та відкат

Пакет зменшує кількість власних console-подій. Автоматичні gateway/runtime logs лишаються. Кількість мережевих звернень та розклад не скорочувалися. Порожня офлайн-черга вже повертається після локального IndexedDB читання без запису до Supabase; сам таймер не є доказом зайвого API-запиту.

Перед deployment зберегти попередній артефакт саме цих функцій. Для відкату опублікувати попередні версії. Не відновлювати весь брудний Git checkout: він містить інші незавершені зміни. Не відкочувати таблиці/дані.

Після deployment перевірити доставку, відсутність повторних доставок, помилки провайдера та конфігурації; порівняти повні дні Usage. Production-розгортання й ці перевірки поки не виконані.

Інструкція узгоджена з [Supabase Logs Query](https://supabase.com/docs/guides/platform/manage-your-usage/logs-query) і [Logs Ingest](https://supabase.com/docs/guides/platform/manage-your-usage/logs-ingest).
