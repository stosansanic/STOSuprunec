# Підказки рядків акта

Пошук найменувань починається з 3 символів після паузи 200 мс. Початкове відкриття рядка не завантажує повні таблиці робіт та деталей. Поточний SQL уже обмежує підказки 50 записами на тип; зміни SQL не потрібні.

Спільний кеш підказок живе до підтвердженого закриття модалки акта, без часового ліміту. Закриття очищає результати та робить пізні відповіді неактуальними. Одночасні однакові запити об'єднуються. Інший рядок використовує ті самі результати. Запити довідників і складу виконуються паралельно.

Коли текст продовжує попередній запит і результат повний (менше 50 у кожному типі), фільтрація виконується локально. Для складу враховано назву та каталожний номер. Якщо сервер повернув 50 збігів, уточнений запит виконується знову, щоб не приховати позиції за межами обмеження. Порожні результати теж кешуються. Зміна початку запиту може вимагати нового запиту.

Кеш скидається при зміні користувача/авторизації, змінах довідників, повідомленні про зміни складу. Помилки не кешуються, застарілі відповіді після зміни контексту відхиляються. Точне визначення рядків при збереженні збережене: неповний кеш не використовується для висновку, що запису немає.

TypeScript перевірку пройдено. Runtime-тести цього разу не запускали. Для застосування оновити frontend на Vercel; SQL і Edge Function не змінювалися.
