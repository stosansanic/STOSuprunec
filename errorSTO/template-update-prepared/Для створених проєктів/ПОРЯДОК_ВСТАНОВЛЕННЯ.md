# Оновлення вже створених проєктів СТО

Підготовлено 11.10.2026 для SQL-частини ТЗ з 29 пунктів. Це комплект для наявної сумісної бази СТО, не для довільної схеми. Нічого не було виконано у віддаленій базі.

## Порядок

1. Зберегти резервну копію чинної бази. Виконати 00_перевірка_передумов.sql: він лише читає схему. Перевірити назви/типи полів, RLS, права та чинні функції; наявність таблиці сама по собі не доводить сумісність. Якщо чогось немає, не запускати файл повного створення/видалення бази поверх чинного проєкту.
2. У Supabase SQL Editor виконати весь 01_функції_читання.sql. Це 42 міграції, вже зібрані у правильному порядку й один transaction. Окремо історичні папки повторювати не потрібно.
3. Далі виконати файли 02–09 у порядку нижче. Перша базова функція — умовний крок. При помилці зупинитися й перевірити причину; не переходити до frontend з неповним SQL.

- **02_20261004000000_write_act_with_stock.sql** — Базова атомарна операція запису акта і складу. Якщо сумісна функція вже встановлена — пропустити; новішу/змінену версію спочатку порівняти.
- **03_20261011040000_stock_reference_resolve.sql** — Пакетне створення/визначення складських довідників.
- **04_20261011050000_stock_invoice_idempotency.sql** — Захист повторного імпорту накладної.
- **05_20261011070000_act_editor_lease_guard.sql** — Перевірка блокування редактора під час запису.
- **06_20261011080000_payroll_fragments.sql** — Атомарні зарплатні фрагменти та захист повтору.
- **07_20261011100000_reminder_delivery_claims.sql** — Claims доставки та lease обчислення нагадувань.
- **08_20261011160000_act_save_receipts.sql** — Короткі квитанції запису акта.
- **09_20261011170000_directory_writes.sql** — Атомарне редагування довідників із збереженням історії.

## Після SQL

- Перенести відповідні зміни frontend з цього проєкту (усі 29 пунктів), зберігши налаштування конкретного проєкту. Самі SQL-функції не змінюють запити старого frontend і не гарантують зменшення трафіку.
- Розгорнути актуальні check-reminders, send-telegram, telegram-bot та їхні спільні модулі, якщо ці функції використовуються проєктом. Перевірити чинні cron: не створювати дублікати. Оновлення nova-poshta — окремий комплект інтеграції, якщо вона встановлена. SQL із цього каталогу не розгортає Edge Functions.
- Зберегти власні URL, ключі, авторизацію, секрети, конфігурацію НП та інших інтеграцій. Секретів у цьому комплекті немає.
- Перевірити запис акта/складу, виплати, повтор накладної, дві сесії редактора, нагадування, звіти, offline/reconnect і права працівників. Після цього порівняти вихідний трафік за однаковими сценаріями.

## Що вже міститься у файлі №8

Оновлений файл «8 зменьшує вихідний трафік.sql» у батьківській папці містить ці самі 42 + 8 міграцій одним transaction для нових проєктів після базової схеми. Вибирайте один спосіб встановлення: файл №8 або цей покроковий комплект, не обидва поспіль. Для чинної бази рекомендовано покроковий комплект із перевіркою наявної write_act_with_stock.

Дати у назвах — версії вихідних міграцій, а не підтвердження їх встановлення. Комплект не створює нових таблиць; додає функції, індекси, тригери й службові поля наявних таблиць. Не запускайте старі міграції Нової пошти або файл «Видалення всього» заради цієї оптимізації.
