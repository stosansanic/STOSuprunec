# Нова пошта для нового проєкту СТО

Комплект підготовлено 11.10.2026 з актуального коду цього репозиторію. Він не містить ключів, паролів або адреси конкретного Supabase-проєкту.

## Що встановлювати

| Файл | Куди / для чого |
|---|---|
| 9 Нова пошта база.sql | Supabase → SQL Editor → New query → вставити весь файл → Run. Повне встановлення модуля поверх базової схеми СТО. |
| 9.1 Нова пошта index.ts | Supabase → Edge Functions → nova-poshta → index.ts. Замінити весь код, потім Deploy. Це TypeScript, не SQL. |
| 9.2 Нова пошта інструкція.md | Ця інструкція. |
| 9.3 Нова пошта створити ключ.ps1 | Локальний PowerShell: створює окремий ключ шифрування для нового проєкту. Не вставляти в SQL Editor. |
| 9.4 Нова пошта оновити наявну.sql | Альтернатива №9 для проєкту, де вже встановлений архів public.novaposhta і базові функції НП. Не потрібно виконувати після №9. |

## Передумови

Спочатку встановіть базову схему СТО (файли основи проєкту). Потрібні сумісні таблиці `settings`, `acts`, `slyusars`, `whitelist`, `clients`, `cars`, Supabase Auth і функція `verify_slyusar_password`. Порожньої бази без основної схеми недостатньо. Використовуйте актуальний frontend цього СТО: SQL і Edge Function самі не додають кнопок до іншого застосунку.

№9 включає налаштування НП, архів, прив'язку актів, підказки пошуку, компактну перевірку працівника та останню міграцію `20261011123102_nova_poshta_infinite_scroll.sql` з RPC `np_archive_list_v2`.

Створюється одна таблиця `public.novaposhta`. Налаштування зберігаються в `settings.novaposhta`, номери ТТН акта — в `acts.novaposhta`, номери пов'язаних актів — у `novaposhta.act_ids`. RLS увімкнений; доступ до архіву здійснюється через серверну функцію. Старі таблиці `np_*` для нового встановлення не потрібні.

## Порядок підключення

1. У потрібному Supabase-проєкті виконайте весь №9 через SQL Editor.
2. Для НОВОГО проєкту відкрийте PowerShell у папці комплекту і виконайте:

   ```powershell
   & '.\9.3 Нова пошта створити ключ.ps1' -ProjectRef 'ВАШ_PROJECT_REF'
   ```

   Замініть `ВАШ_PROJECT_REF` реальним ідентифікатором проєкту з 20 малих латинських літер/цифр. Поряд створиться `nova-poshta-<ref>.secrets.env`. Відкрийте його локально й додайте значення `NP_ENCRYPTION_KEY` у Supabase → Edge Functions → Secrets. Зберігайте файл приватно, не в Git і не у frontend. Для проєкту з уже налаштованою НП залиште чинний ключ: його заміна зробить збережені облікові дані непридатними для розшифрування.
3. Створіть або відкрийте Edge Function з точною назвою `nova-poshta`. Вставте ВЕСЬ №9.1 замість `index.ts`. Локальна залежність `_shared/nova-poshta-domain.ts` уже вбудована в цей файл; вручну додавати її не потрібно. Зовнішній npm-імпорт Supabase залишається і завантажується під час розгортання.
4. Для цієї функції вимкніть **Verify JWT / Enforce JWT verification** шлюзу й натисніть Deploy. Код сам перевіряє користувацький JWT через Supabase Auth, whitelist та сесію працівника. Серверний ключ Supabase береться із середовища Edge, його не можна переносити до браузера.
5. За потреби додайте секрет `ALLOWED_ORIGINS`: дозволені адреси сайтів через кому, наприклад `https://example.com,https://app.example.com`, без шляхів і кінцевого `/`.
6. Налаштуйте frontend копії СТО на URL і публічний ключ нового Supabase через `VITE_SUPABASE_URL` та `VITE_SUPABASE_KEY`. Опублікуйте актуальний frontend. Не копіюйте секрети, `.vercel` або `.env.local` попереднього проєкту.
7. Додайте потрібних користувачів у whitelist та працівників у систему. У програмі відкрийте «Нова пошта», підтвердьте пароль працівника. Адміністратор вводить телефон, API-ключ та, за потреби, логін/пароль НП у налаштуваннях модуля.
8. Натисніть «Оновити з Нової пошти» для первинного наповнення архіву. Перевірте відкриття ТТН і прив'язку до потрібного акта.

## Поточна поведінка

- За замовчуванням початковий список охоплює всі збережені ТТН за останні 14 календарних днів. При прокрутці додаються старіші ТТН по 10. Вручну вибраний інший період залишається обмеженням пошуку.
- Звичайне відкриття читає збережений архів. API НП викликається явним оновленням. Оновлення списку НП використовує вибрані дати, а не всю історію.
- Якщо відправлення зникло в НП, його збережений запис не видаляється. Зміни полів зберігаються з історією; однакова відповідь не потребує повторного запису.
- Повні відповіді та історія читаються окремо при відкритті відповідного блоку деталей.

## Оновлення вже підключеного проєкту

Якщо архів `novaposhta` і базова інтеграція вже є: виконайте №9.4, оновіть Edge Function кодом №9.1 та опублікуйте актуальний frontend. Чинний `NP_ENCRYPTION_KEY` залиште. №9.4 потребує попередньо встановленої базової інтеграції; для нового проєкту використовуйте №9.

## Відтворення комплекту розробником

У корені актуального репозиторію:

```powershell
node scripts/prepare-nova-poshta-template.cjs
```

Файли будуть у `errorSTO/template-update-prepared/nova-poshta`. Генератор не читає секретів і не виконує SQL або deploy. Канонічні джерела: `supabase/setup/nova-poshta.sql`, міграції архіву від 03.10.2026, компактні employee RPC з `20261005130000_traffic_reports.sql`, міграція підвантаження від 11.10.2026, `supabase/functions/nova-poshta/index.ts` і `_shared/nova-poshta-domain.ts`.

Документація розгортання Supabase: https://supabase.com/docs/guides/functions/deploy
