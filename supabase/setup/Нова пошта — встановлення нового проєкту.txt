НОВА ПОШТА — ВСТАНОВЛЕННЯ В НОВОМУ ПРОЄКТІ

Склад комплекту
- 9 Нова пошта база.sql — SQL-об’єкти модуля Нової пошти та його залежності.
- 9.2 НП Index Edge Functions → nova-poshta → Code Edit code..ts — повний код Edge Function nova-poshta для Supabase Dashboard; додаткові імпортовані файли не потрібні.
- 9.1 НП Index Edge Functions → check-reminders..sql — це TypeScript функції check-reminders, попри розширення .sql. НЕ запускайте цей файл у SQL Editor. Він не є частиною модуля Нової пошти; розгортайте окремо лише якщо потрібні нагадування.

Передумови
Це доповнення до системи СТО, а не створення всієї бази з нуля. Спочатку встановіть базові SQL-міграції проєкту: таблиці settings, acts, slyusars, whitelist, авторизацію та RPC verify_slyusar_password. Для основного проєкту перевірте, що всі залежності файлу №9 існують.

Встановлення Нової пошти
1. Відкрийте саме новий Supabase-проєкт → SQL Editor → New query.
2. Вставте весь файл «9 Нова пошта база.sql» і виконайте його один раз. Перевірте, що результат — Success. Не виконуйте файл check-reminders у SQL Editor.
3. У Supabase → Edge Functions створіть або відкрийте функцію з назвою nova-poshta.
4. Відкрийте функцію, замініть весь вміст index.ts кодом із файлу 9.2. Не додавайте код у кінець старого файла — замініть його повністю.
5. У налаштуваннях функції вимкніть Verify JWT / Enforce JWT verification, якщо ця опція ввімкнена. Функція перевіряє Supabase JWT і права працівника всередині коду.
6. Додайте секрет NP_ENCRYPTION_KEY у Secrets. Створіть окремий випадковий секрет для кожного Supabase-проєкту; не копіюйте ключ з іншого проєкту й не вставляйте його у SQL або frontend. Для повторного розгортання в тому самому проєкті збережіть раніше встановлений ключ — він потрібний для розшифрування збережених облікових даних Нової пошти.
7. Натисніть Deploy для nova-poshta.
8. Налаштуйте frontend на URL і публічний ключ саме цього Supabase-проєкту та опублікуйте frontend.
9. У застосунку відкрийте розділ Нової пошти, увійдіть як працівник і заповніть параметри інтеграції. Перевірте читання архіву та ручне оновлення ТТН.

Перевірка
- У SQL Editor функція public.traffic_np_request_context(uuid,text,text,bigint,text,text) має існувати.
- У файлі 9.2 є виклик traffic_np_request_context; це очікувано.
- У Edge Function nova-poshta статус після Deploy має бути Active.
- Не вставляйте service_role key або NP_ENCRYPTION_KEY у frontend, SQL-скрипт чи повідомлення.
- Ці файли не розгортають застосунок автоматично і не змінюють Supabase, поки ви самі не виконаєте кроки вище.

Оновлення існуючого проєкту
Зробіть резервну копію перед оновленням. Виконайте SQL №9, замініть код nova-poshta повністю на файл 9.2 і збережіть незмінним наявний NP_ENCRYPTION_KEY. Не створюйте новий ключ для проєкту з уже зашифрованими даними.
