ОНОВЛЕННЯ POSTGREST — 23.10.2026

Для поточного СТО: Supabase project ref eksifjzzszcqsufwcbsx.
Для Wolfdrive або іншого СТО виберіть саме його Supabase-проєкт.
Цей комплект підготовлено локально; він ще не встановлений у робочій базі.

1. SQL
Відкрийте Supabase → ваш проєкт → SQL Editor → New query.
Вставте ВЕСЬ вміст 01-database-9.1.sql і натисніть Run.
Це точна копія «9.1 Оптимізація PostgREST.sql».
Очікуваний результат: Success. No rows returned.
Якщо з'явилася SQL-помилка, спочатку виправте її; код функцій і сайт оновлюйте після успішного SQL.
Файл 8 використовується для встановлення нового проєкту після базової схеми 1–7.

2. NOVA-POSHTA
Відкрийте Edge Functions → наявна nova-poshta → Code / Edit code.
Перед заміною збережіть локально поточний index.ts для можливого повернення.
Замініть весь вміст index.ts кодом із 02-nova-poshta-index.ts.
Натисніть Deploy updates / Deploy і дочекайтеся успішного завершення.
Локальна залежність nova-poshta-domain.ts вже включена в цей файл.

3. CHECK-REMINDERS
Відкрийте Edge Functions → наявна check-reminders → Code / Edit code.
Збережіть поточний index.ts, потім замініть його весь кодом із 03-check-reminders-index.ts.
Натисніть Deploy updates / Deploy і дочекайтеся успішного завершення.
operationalLog.ts, reminderDelivery.ts і resultDigest.ts вже включені.
Обидва файли використовують явний npm-імпорт @supabase/supabase-js@2.98.0.

4. НАЛАШТУВАННЯ
Збережіть поточні значення Verify JWT для кожної функції. Локальні файли не показують їхнього чинного стану на сервері.
Збережіть наявний NP_ENCRYPTION_KEY у Edge Functions → Secrets: інший ключ не розшифрує раніше збережені дані НП.
Секрети вводяться у Secrets, а SQL — у SQL Editor. У коді цього комплекту значень секретів немає.
Нові змінні Vercel чи Supabase для цієї оптимізації не потрібні.
Не створюйте другий cron для check-reminders. Використовуйте чинний розклад.

5. САЙТ
Після SQL і двох функцій розгорніть оновлений сайт у Vercel зі звичного проєкту.
Оновіть вкладку браузера та перевірте потрібні розділи.

6. ПЕРЕВІРКА
У Logs / Invocations перевірте наступні звичайні звернення на відсутність 404, 500, BOOT_ERROR і помилок відсутніх RPC.
Для check-reminders дочекайтеся чинного запуску за розкладом, якщо є активні Telegram-нагадування.
Не використовуйте ручний Test як безпечну перевірку: GET/POST цієї функції з допустимими заголовками запускає реальну обробку та може надіслати повідомлення. Режиму dry_run немає.
Тільки OPTIONS у check-reminders завершується без обробки нагадувань; він перевіряє запуск/CORS, а не доставку.
Внутрішня перевірка заголовків check-reminders наразі не є повноцінною перевіркою токена. Не вимикайте Verify JWT для усунення 401 без окремого узгодження авторизації cron.

Повторна генерація комплекту з поточного коду:
node scripts/prepare-postgrest-edge-dashboard.cjs

Основні джерела залишаються у supabase/functions/nova-poshta,
supabase/functions/check-reminders і supabase/functions/_shared.
